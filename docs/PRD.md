## 1. 背景与问题

原神、明日方舟等长线运营游戏的玩家在日常攻略中面临三类信息痛点：

1. **资料分散**：角色技能数值、材料掉落、卡池时间、配队推荐散落在 BWIKI、PRTS、B站视频、官方公告等多个来源，玩家要在 3–5 个站点间反复切换；
2. **信息时效差**：版本更新后攻略滞后，玩家查到的可能是旧版本数据；
3. **规划成本高**：抽卡预算计算、角色养成材料清单、排期需要玩家自己查表估算，容易漏项或算错。

现有方案（通用大模型直接问答）的问题是：**容易编造游戏数值**（"幻觉"），玩家不敢直接信。

## 2. 目标与非目标

### 2.1 产品目标

- 让玩家用一句自然语言，在一个对话框里拿到**可溯源、不编造**的游戏资料；
- 覆盖"查资料 → 做规划 → 保存计划"的完整闭环，而不只是单跳问答；
- 个人/小团队可部署（打包 EXE 或 Docker 一键起），不依赖重型后端。

### 2.2 非目标（本期不做）

- 不做游戏代练、自动挂机、抽卡模拟；
- 不做社区/UGC 攻略分享；
- 不做实时对战辅助（破坏游戏公平性）；
- 不做多游戏之外的通用问答（如闲聊、写代码）。

## 3. 目标用户与场景

| 用户画像 | 典型场景 |
|---|---|
| 原神/明日方舟活跃玩家（18–30 岁） | 查角色技能数值、问材料需求、算抽卡预算、查活动时间 |
| 新入坑玩家 | 不知道该练谁、材料从哪刷，需要一份养成清单 |
| 回归玩家 | 版本更新后跟不上，需要快速对齐当前卡池和活动 |

## 4. 功能需求

### 4.1 P0 核心问答

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F1 | 自然语言提问，Agent 自动识别游戏（原神/方舟）并路由到对应知识包 | 连续问不同游戏不串数据 |
| F2 | 实体查询（角色/武器/干员/材料）返回结构化数值，附引用来源 | 回答中可点击查看出处（BWIKI/PRTS） |
| F3 | 混合检索：名称置顶 + 向量 + BM25 + 关键词 + 元素×职能结构化查询 | 角色名、昵称、别称都能命中 |
| F4 | 官方 wiki 数据优先，LLM 仅补缺；未收录时明确说"资料未收录"而非编造 | 30 条评测集 0 幻觉 |
| F5 | SSE 流式输出，前端实时渲染决策链路（检索了什么、调了哪个工具） | 用户能看到 Agent 思考过程 |

### 4.2 P1 规划闭环

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F6 | 养成规划：输入角色名 + 当前资源，输出材料清单（摩拉/经验书/宝石/特产/天赋书）+ 抽卡预算（小/大保底对比、缺口）+ 多步排期 | 材料数值与官方 wiki 一致 |
| F7 | 计划保存：用户确认后写入 SQLite，按会话回读、删除 | 刷新页面后计划不丢 |
| F8 | 重大事件查询：卡池/活动/前瞻时间线，剩余天数按 UTC+8 计算 | 剩余天数与官方公告一致 |

### 4.3 P2 增强

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F9 | 截图识别：用户上传游戏截图，多模态模型识别角色/界面并回答 | 常见角色立绘识别正确 |
| F10 | 配队分析：基于游戏内职业规则给出配队建议 | 不编造角色机制 |
| F11 | 会话记忆：跨会话记住用户常用角色和偏好 | 第二次问不用重复说角色 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单轮问答 P95 < 8s（含 LLM 调用）；向量检索 P95 < 200ms |
| 部署 | 支持 Docker 双容器一键起；也可打包 Windows EXE 离线运行 |
| 数据合规 | 仅采集公开 wiki 数据，遵守 robots 和限流；不登录、不爬付费内容 |
| 可观测 | 全链路 LLM token 用量统计；SSE 事件流可追踪 |
| 评测 | 223 条评测集（规则判定 + LLM-as-Judge），每次改动可回归 |

## 6. 用户流程

```
用户输入问题
  → Agent 识别游戏 + 意图
  → 路由到对应子代理（原神/方舟/通用知识）
  → 混合检索 + 工具调用（≤3 轮）
  → 必要时重规划（≤1 轮）
  → 合成回答 + 自检（幻觉/覆盖度）
  → SSE 流式返回前端
  → 用户追问 / 保存规划 / 结束会话
```

## 7. 成功指标

| 指标 | 目标 | 当前值 |
|---|---|---|
| 问答准确率（规则判定） | ≥ 0.90 | 0.947（170 条 numeric 集） |
| 幻觉率 | ≤ 5% | 6%（judge 50 条中 3 条） |
| RAG 命中率 | ≥ 0.90 | 0.947 |
| 单轮 token 成本 | < 15k | 13.9k/条 |

## 8. 风险与边界

- **数据时效**：游戏版本更新后 wiki 数据可能滞后，通过每日预热 cron + 用户反馈闭环补录；
- **LLM 成本**：多轮工具调用烧 token，通过上下文预算（最近 8 条 + 摘要压缩）控制；
- **第三方依赖**：BWIKI/PRTS 限流时降级到本地静态库，不影响核心问答；
- **不做的事**：不爬登录态数据、不做自动化外挂、不存储用户隐私。

## 9. 后续路线

- 短期：扩游戏库（星铁/绝区零）、提升 knowledge 类题召回率；
- 中期：多用户服务端模式（替换 Chroma 本地模式）、计划分享；
- 长期：开放知识库接入，让玩家自建攻略包。
