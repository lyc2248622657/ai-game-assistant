## 五、面试怎么讲（全部用真实事实）

### 5.1 1 分钟版（按文档"背景→目标→方案→职责→结果"）

> 这个项目面向"游戏资料分散、不同来源的答案互相矛盾"的场景，做一个能自动判断游戏、检索官方资料再回答的助手。方案上分三层：检索层用名称强匹配置顶加向量与 BM25 多路召回、再按名次融合；编排层用 LangGraph 做了 8 个节点的链路，主管节点先判断问题属于哪个游戏、哪一类任务，再委派给子代理调工具，执行完还会做一次重规划和一次质检回炉，异常则收敛到兜底节点；工程层是 FastAPI 的 26 个接口，含 SSE 流式推送，前端能把 Agent 的每一步决策实时展示出来。我重点负责检索融合与链路稳定性，其中比较关键的是发现"跨会话记忆明明检索到了、却没进提示词"——最后定位到框架只认已声明的状态通道，写入被静默丢弃；补上通道后加了回归测试锁住这个行为。

### 5.2 八个高频追问的标准答法

**Q1「你具体做了什么？」**（文档：模块→动作→问题→结果）
> 我负责的是检索融合、状态与错误契约、以及数据持久化这三块。不是所有部分都从零手写——页面和部分工具实现有 AI 辅助的成分。我这部分最能拿出来讲的是三个具体问题：记忆注入失效、SQLite 连接泄漏、BM25 压制向量召回，每个都有定位过程和验证方式。

**Q2「是不是 AI 帮你做的？」**（文档：不能回避，也不能心虚）
> 是的，AI 参与度比较高，我用它做代码生成、定位辅助和测试补充。但需求拆解、方案取舍、结果验证和收口是我做的。举个具体例子：AI 生成的修复方案里，"检索融合"一开始是把两个分数取最大值，看起来能跑，但实际是词法命中必然赢过语义命中；这个必须靠理解分数尺度才能判断，不是跑通就算完。

**Q3「你遇到最难的地方是什么？」**
> 不是把功能跑起来，而是"看起来正常、其实没生效"这类静默失败。记忆那条链路最难：日志显示检索有结果，但下游提示词里始终没有，因为框架对未声明字段只打一条 warning 就丢弃。定位方式是先用 AST 把"代码里读写的状态键"和"类型声明里的键"做差集，再回到框架源码确认写入逻辑。

**Q4「怎么验证 AI 生成的内容是对的？」**（文档：核心是质量意识）
> 我按任务类型分层验证：代码生成看结构和边界（编译 + 静态检查 + 关键流程回归）；涉及契约的改动一定写回归测试，比如状态通道这条我加了一个真的跑 LangGraph 小图的用例，断言"声明过的通道能跨节点传递"；涉及数字的结论一律回到原始数据核对——这也是我发现评测指标不可信的原因。

**Q5「怎么评估效果？」**（⚠️ 目前是弱项，按文档"诚实说"）
> 现在有 220 条评测集，分规则判定和 LLM 评审两类，但不硬：规则判定早期用的是"标准答案是否是回答子串"，对"水/火/5星"这类短答案会虚高；LLM 评审又和被测模型是同一个模型，存在自评偏差。所以我现在只敢讲方法和发现的问题，不敢讲具体准确率。下一步我会把规则判定改成结构化字段比对，评审换独立模型并固定 seed。

**Q6「怎么控制幻觉？」**
> 三层：检索层强制引用来源，回答只围绕命中实体；生成层在提示词里要求"资料未覆盖就明说"，检索为空时走工具重试而不是直接编；数据层对 LLM 生成条目做 wiki 交叉验证。但要诚实说，交叉验证目前只是记录冲突、没有阻断入库，这条是我下一步要收紧的。

**Q7「工具调用失败怎么办？」**
> 工具有一次自动重试，仍失败则把错误作为工具结果回给模型，让它决定换工具还是收敛；整条链路有兜底节点，状态里带 error 时会改道到兜底回答。这里我修过一个真实问题：兜底节点定义了但**没有任何边指向它**，等于死代码——注释写着"统一收敛点"，实际永远不执行。

**Q8「如果再做一版，最想优化什么？」**（文档：看复盘与边界感）
> 三个：① 上下文预算——现在把检索结果的完整 JSON 拼进提示词，实测方舟单轮资料就有 26KB、约 17k tokens，应该按字段白名单+长度截断；② 评测可信度——把子串判定换成结构化断言，评审换模型；③ 数据层治理——统一 ID 规范、动态缓存写入加守卫。这三条都不是"加功能"，而是让已有能力更可信。

### 5.3 面试官现场让你加一个角色怎么办

这不是刁难，是验证数据管道。当前真实状态：静态库 `genshin/characters.json` 是空数组、id 有 4 种风格、动态缓存写入没有守卫。
**建议面试前先修掉这三点**（见 §六），否则这一问会很难看。

1. **项目够用了，问题在表述**：把"功能清单"改成"场景 → 我做了什么 → 我踩了什么坑 → 怎么验证"，立刻从 demo 变成作品。
